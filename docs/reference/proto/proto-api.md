### Service ApprovalService

ApprovalService shows and decides ask-tier tool calls (ADRs 0008, 0042,
0049; plan item P1). An agent's call is recorded exactly; approving it binds
to the SHA-256 of its canonical arguments, and Koinon then executes exactly
that call (for create_pull_request: the branch, the commit and the pull
request through the GitHub API; the agent never pushes) and resumes the
parked run with the result. Viewers see every request; only admins and
owners decide (ADR 0049: the default approver policy).

| Method | Request | Response | Streaming | Description |
| --- | --- | --- | --- | --- |
| Approve | `koinon.approval.v1alpha1.ApproveRequest` | `koinon.approval.v1alpha1.ApproveResponse` | - | Approve approves a pending request and executes it. args_sha256 must be the hash shown with the request; a different hash fails with ABORTED (HTTP 409) and nothing is executed. A request that is no longer pending fails with FAILED_PRECONDITION. Approving again with the same hash returns the request as it is (the same pull request), without executing it again. ## koinon.connection.v1alpha1

### Service ConnectionService

ConnectionService manages an org's connections to external systems
(ADR 0007): one configured instance of a connector type, such as one GitHub

## koinon.gateway.v1alpha1

### Service GatewayStateService

GatewayStateService is the State stream of ADR 0097 decision 2.1: koinon-api sends a gateway copy
the full desired state of the gateway, one revision at a time, and the copy confirms each half of a
revision once it serves it. It is the config delivery of Koinon's own gateway; the agentgateway
drivers keep rendering files and CRDs. It is internal: only a gateway copy calls it.

Nothing here carries secret material: a StateUpdate holds key ids and key hashes, never a key, and
names the file a credential is mounted at, never its content (ADR 0097 decision 5, the secret store).

| AckRevision | `koinon.gateway.v1alpha1.AckRevisionRequest` | `koinon.gateway.v1alpha1.AckRevisionResponse` | - | AckRevision tells koinon-api that the copy serves one half of a revision. A copy acks the model half and the MCP half apart, because the two paths are applied apart (MCPGateway.ApplyMCP). An ack of a revision covers every earlier one for that half. Idempotent. |
| StreamState | `koinon.gateway.v1alpha1.StreamStateRequest` | `koinon.gateway.v1alpha1.StateUpdate` | server | StreamState sends the latest revision at once and every later one when it is published. ### Service McpServerService

McpServerService manages an org's remote MCP servers (ADR 0057) for the UI. It is the connect-rpc
face of the same service layer the admin API uses, so validation, the upstream URL policy and the
audit trail are the same. Admins and owners only: members do not see servers.

### Message HomeBackupRetention

HomeBackupRetention is the org's effective retention of old home backup repositories. A key change
starts a new backup repository for each agent's home; the old one stays readable for the
checkpoints written to it for days, then it is deleted. The deadline is set when the new repository
starts, so a change applies to later key changes only.

### Message RunContentRetention

RunContentRetention is the org's effective retention of stored run content. Once a finished run is
older than days, the purge job blanks the payload of its content events (messages, thoughts and tool
calls) and strips the text from prompt, permission and refusal events, whose state fields stay. Other
events, the run's status, traces and the spend ledger stay.

## koinon.outward.v1alpha1

Files: `koinon/outward/v1alpha1/outward.proto`

### Service OutwardService

OutwardService is the one switch for everything Koinon calls outside the install (ADR 0110 decision 5):
MCP servers, model providers, code-host connections and trace destinations. A disabled target is not
called, not probed and not offered to runs; it keeps its bindings and its credential. It is the
connect-rpc face of the same service layer the admin REST API uses. Every change is audited as
outward.disable or outward.enable.

| Method | Request | Response | Streaming | Description |
| --- | --- | --- | --- | --- |
| SetOutwardTargetDisabled | `koinon.outward.v1alpha1.SetOutwardTargetDisabledRequest` | `koinon.outward.v1alpha1.SetOutwardTargetDisabledResponse` | - | SetOutwardTargetDisabled disables or enables one target. Org admins and owners switch the org's own targets; the platform trace destination needs a platform admin. Disabling is allowed while the install is held for a restore; enabling is refused then with FAILED_PRECONDITION. A target whose declaring Secret says disabled: true cannot be enabled here (FAILED_PRECONDITION). Setting the state a target already has changes and audits nothing. |

## koinon.provider.v1alpha1

Files: `koinon/provider/v1alpha1/provider.proto`

### Service ProviderService

ProviderService manages an org's model providers and models (ADR 0056) for the UI. It is the
connect-rpc face of the same service layer the admin API uses, so validation, the upstream URL
policy and the audit trail are the same. Admins and owners only: members do not see providers.

Entries declared by a labelled Kubernetes Secret (source "secret") are read-only: changing or
deleting a live one fails with FAILED_PRECONDITION and names the Secret. Provider keys are write-only;
they are never returned.

## koinon.trace.v1alpha1

Files: `koinon/trace/v1alpha1/trace.proto`

### Service TraceDestinationService

TraceDestinationService manages where run traces go (ADR 0074): an org's OTLP destinations, its
content level and sampling, and, for platform admins, the platform's destination and the ceiling on
content levels.

Org calls need the admin role; only an owner may set the content level full. Platform calls need a
platform admin. Credentials are write-only: they are sealed in the secret store and never returned.
Creating or changing a destination's connection (backend, endpoint, settings or secrets) first sends
it one synthetic trace and saves only when the backend accepts it (decision 9): a refusal is
FAILED_PRECONDITION and the message says why. A change that touches none of those (enabled, name,
resource attributes) is saved untested, so a destination whose backend is down can still be disabled.
Stored secrets are kept only while backend and endpoint origin stay the same; otherwise every secret
is required again. While the org's effective content level is full, only an owner may add a
destination or change its connection.

Failures carry a machine-readable reason as a google.rpc.ErrorInfo error detail (domain "koinon.dev",
reason below, the human message stays in the error). Read it by unpacking the details of the error.

	PERMISSION_DENIED  ADMIN_REQUIRED          the org call needs the admin role or higher
	                   PLATFORM_ADMIN_REQUIRED the platform call needs a platform admin
	                   OWNER_ONLY              only an org owner may set the content level or the platform copy to full
	                   OWNER_AT_FULL           the org's level is full, so only an owner may add a destination or change its connection
	                   NOT_MEMBER              raising a level needs membership of the org (a platform admin outside it may only lower)
	FAILED_PRECONDITION TEST_FAILED            the test trace was not accepted, nothing was saved; the details also hold a
	                                           koinon.trace.v1alpha1.TestResult with the outcome alone (no prefix)
	                   ABOVE_CEILING           the level is above the platform ceiling
	ABORTED            CHANGED                 the destination changed (or was deleted) since the form was loaded
