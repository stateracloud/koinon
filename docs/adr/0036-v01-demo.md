# 0036. v0.1 demo: a 15-minute quickstart ending in one approved GitHub action

- Status: Accepted
- Amended by: [0049](0049-v01-scope-decisions.md), [0062](0062-code-host-connectors.md), [0065](0065-work-model-tasks-inbox.md)
- Date: 2026-10-21
- Decision: [design.md#36](../design.md)
- Verification: done by the OpenShell spike, see [0048](0048-openshell-spike-results.md) (was: Pending: OpenShell spike, old issue 3)

## Context

v0.1 needs to show the core promise: a useful agent that is safe by default. The roadmap
([0024](0024-roadmap.md)) puts the full connector framework in v0.2. But a demo without a real
external system doesn't show why approvals and credential isolation matter, so the GitHub connector
moves into v0.1.

Since the grilling session, the ask tier has moved from OpenShell into Koinon. Ask-tier actions are
MCP tools behind agentgateway, the run parks, and Koinon executes the exact approved call
([0042](0042-ask-tier-park-and-execute.md)). The demo's approval step therefore depends on that path.

## Decision

The v0.1 quickstart takes **15 minutes** and has five steps:

1. **Install:** `helm install` Koinon on a cluster that already has Agent Sandbox, OpenShell and
   Kata. The chart wires the Koinon API, reconciler, Postgres and agentgateway.
2. **Create an agent from a template:** pick a template, choose a flavor
   ([0035](0035-v01-flavors.md)), and connect GitHub.
3. **Message it:** create a ticket from the board, or chat on the ticket.
4. **Watch the run live:** the ticket view streams the run's events.
5. **Approve one GitHub action:** the agent proposes, for example, opening a pull request. The run
   parks. The approval card shows the exact call. After approval, Koinon executes that call and
   the run resumes.

Components v0.1 needs for the demo:

- **GitHub connector, as a GitHub App:**
  - Installation tokens last 1 hour and are narrowed per request to the granted repositories and
    permissions (`contents`, `pull_requests`, `issues`).
  - The token never enters the sandbox: it lives in an OpenShell provider record for read-tier
    calls, and Koinon uses it directly for executing approved ask-tier calls.
- **agentgateway** as the model gateway and the MCP gateway
  ([0040](0040-agentgateway-model-and-mcp-gateway.md)), with a GitHub MCP tool set split by risk
  tier.
- **An approval service** that parks the run, renders the approval card, executes the approved call
  with an idempotency key, and resumes the session ([0042](0042-ask-tier-park-and-execute.md)).
- **A minimal spend ledger** so the demo shows cost per ticket
  ([0041](0041-koinon-spend-ledger-and-budget-stops.md)) _(inferred, may be trimmed)_.

**Amendment ([0049](0049-v01-scope-decisions.md)).** The open questions below are settled: the
template is a repo helper; the GitHub scopes are `repo.read`, `pull_request.create` and
`issue.comment`; v0.1 ships the board, ticket view, agent-from-template form, approval card and a
GitHub connection page; the 15 minutes start at `helm install`, with prerequisites in place.

## Alternatives considered

- **Demo with no external connector** (a local repo only) _(reconstructed)_: smaller, but it
  doesn't show approvals or credential isolation.
- **Slack as the first connector** _(reconstructed)_: a good fit for chat, but less obvious as a
  "risky action" than opening a PR.
- **Hold the call open until approved** instead of park-and-execute: rejected in
  [0042](0042-ask-tier-park-and-execute.md).

## Consequences

- Positive:
  - A concrete, end-to-end target for v0.1 issues.
  - Exercises the riskiest seams: credentials, policy, approvals and resume.
- Negative:
  - The v0.1 scope grows: agentgateway, the approval service and a GitHub App all move earlier than
    the v0.2 connector framework.
  - The demo needs a GitHub App the user installs; the setup guide must make that fast
    ([0021](0021-connector-setup-guides.md)) _(inferred)_.
- Follow-ups:
  - The v0.1 milestone plan (old issue 4) derives its
    issues from these five steps.
  - The quickstart is an e2e test on kind (minus Kata) and on the home lab with Kata
    ([0025](0025-testing-strategy.md)) _(inferred)_.

## Open questions

These are listed as "still open" in `BOOTSTRAP.md` and are settled in the v0.1 plan:

- What the v0.1 template agent does (for example "triage issues and open a fix PR").
- The GitHub connector's v0.1 scopes and their tier assignment.
- Which UI parts ship in v0.1: board, ticket view, agent from template, approval card.
- Can 15 minutes include installing the prerequisites (Agent Sandbox, OpenShell, Kata), or do they
  have to be in place already?

## Upstream verification

Checked 2026-10-21:

- **GitHub App installation tokens:** expire after 1 hour, and can be narrowed by `repositories` and
  `permissions`.
  https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app
- **agentgateway:** MCP authorization on tool name and arguments through CEL, and the ExtMCP
  callout. https://agentgateway.dev/docs/standalone/main/configuration/security/mcp-authz/
- **OpenShell:** placeholder credentials and policy enforcement are pending the spike
  (old issue 3).
