# 8.16: Kata annotation turning guest seccomp off

Run 2026-10-21T14:16:44Z. Plain pods (not OpenShell) with the workload label, `runtimeClassName: kata`, `seccompProfile: RuntimeDefault`, busybox printing its own seccomp status. Only Kata applies seccomp here, so `Seccomp: 0` means guest seccomp is off.

```
$ kubectl apply pod a16-control (annotations: {})   # 14:16:44Z
pod/a16-control created
$ kubectl apply pod a16-annotated (annotations: {"io.katacontainers.config.runtime.disable_guest_seccomp":"true"})   # 14:16:45Z
pod/a16-annotated created
$ kubectl logs a16-control   # 14:17:26Z
Seccomp:	2
Seccomp_filters:	1
$ kubectl logs a16-annotated   # 14:17:26Z
Seccomp:	0
Seccomp_filters:	0
```

## With the VAP rule

Rule added to `hack/spike/manifests/sandbox-vap.yaml`: reject any `io.katacontainers.*` annotation on pods in OpenShell-managed namespaces.
